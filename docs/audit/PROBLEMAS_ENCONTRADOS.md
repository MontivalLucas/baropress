## Pendências que exigem decisão ou ambiente
- **SEC-01 — ALTO, decisão estrutural:** SQLite e backups JSON não são cifrados. Reproduzir com cópia sintética do arquivo: dados podem ser lidos fora do aplicativo por quem tenha acesso ao arquivo. O login protege comandos do app, não substitui as permissões do Windows. Cifrar exige definir chave, recuperação, política de backup e migração; não aplicado sem decisão.
- **SCI-01 — MÉDIO, decisão sobre regra de medição:** threshold 0 faz calculateMetrics contar sensels com valor zero como contato, por comparação >=. Reproduzir no código com 225 zeros e threshold 0: área 100%, CoP nulo. A regra atual foi preservada conforme proibição de alterar regras clínicas; decidir entre threshold mínimo positivo ou exclusão explícita de zero.
- **UX-04 — BAIXO, decisão de produto:** limites de antropometria divergem entre atributos HTML, validação React e backend (altura/peso/calçado). Não unifiquei faixas clínicas por conta própria.
- **PERF-01 — MÉDIO, risco a medir:** listas de pacientes/exames e comparação carregam resultados completos; não há paginação. Ainda não houve ensaio de base volumosa nem perfil de CPU/memória.
- **HIST-01 — MÉDIO, decisão de produto:** relatórios usam nome/antropometria atuais do paciente via JOIN; ajustes e matriz do exame são históricos, mas os dados demográficos não têm snapshot no exame. Nova persistência exigiria modelo/versionamento, sem inventar dados antigos.
- **UI-TEST — BLOQUEADO:** Computer Use localizou a janela isolada, mas get_window_state retornou “Computer Use app approval timed out”. Nenhum clique ou captura de tela validou fluxos; usar CHECKLIST_MANUAL.md.
- **HW-TEST — NÃO TESTADO:** ESP32, Bluetooth SPP e impressora reais não foram usados. BLE nativo não é uma funcionalidade implementada.

Recursos inexistentes como restaurar paciente arquivado, gerenciar múltiplas clínicas, autenticação externa, BLE e perfis clínicos completos são escopo futuro, não classificados automaticamente como botões defeituosos.
