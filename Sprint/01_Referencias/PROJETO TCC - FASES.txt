# 2. CONTEXTO DO HARDWARE

O projeto possui uma esteira/plataforma de pressão plantar baseada em:

* ESP32 Dev Module / NodeMCU-32S;
* matriz resistiva 15 × 15;
* 225 pontos de medição;
* Velostat;
* fitas condutoras de cobre;
* dois multiplexadores CD74HC4067;
* ADC do ESP32;
* comunicação USB Serial;
* comunicação Bluetooth Serial SPP.

A matriz possui:

225 sensels = 15 linhas × 15 colunas.

O Velostat apresenta comportamento piezorresistivo: sua resistência diminui conforme a pressão aplicada.

O sistema atual já consegue:

* realizar varredura 15×15;
* receber 225 valores;
* transmitir via USB;
* transmitir via Bluetooth;
* trabalhar a aproximadamente 30 FPS;
* realizar tara automática;
* aplicar threshold;
* aplicar escala máxima;
* aplicar correção gama;
* exibir mapa de calor;
* calcular distribuição de pressão entre pé esquerdo e direito.

# 3. PINAGEM REAL DO ESP32

NÃO altere esses pinos sem necessidade.

## MUX 2 — leitura analógica

SIG → GPIO 34 / D34

S0 → GPIO 18 / D18

S1 → GPIO 19 / D19

S2 → GPIO 21 / D21

S3 → GPIO 22 / D22

GPIO 34 é utilizado como entrada ADC.

## MUX 1 — excitação das linhas

SIG → GPIO 12 / D12

S0 → GPIO 25 / D25

S1 → GPIO 26 / D26

S2 → GPIO 27 / D27

S3 → GPIO 14 / D14

## Matriz

ROWS = 15

COLS = 15

Total = 225 sensores.

---

# 4. PROTOCOLO ATUAL DO ESP32

O ESP32 envia uma linha contendo:

225 valores inteiros separados por vírgula.

Exemplo:

123,125,127,130,...,500

A linha termina com:

\n

Baud rate:

115200

Nome Bluetooth atual:

Esteira_Pressao_ESP32

O software deve ser capaz de receber esse protocolo.

NÃO altere o firmware existente inicialmente.

Crie a aplicação de forma que ela consiga funcionar com o protocolo atual.

No futuro poderemos criar um protocolo versionado.

---

# 5. PROCESSAMENTO ATUAL

O processamento atual utiliza:

1. aquisição dos 225 valores;
2. conversão para matriz 15×15;
3. inversão horizontal da matriz quando necessário;
4. calibração/tara;
5. subtração da linha de base;
6. threshold;
7. clipping;
8. normalização;
9. correção gama;
10. renderização do mapa de calor.

A lógica atual utiliza aproximadamente:

VMAX padrão: 2200

Threshold padrão: 150

Gamma padrão: 1.3

Esses valores devem ser CONFIGURÁVEIS.

Não considere esses valores como calibração universal ou medida física de pressão.

O sistema deve deixar claro que os valores ADC são dados relativos do sensor enquanto não existir uma calibração física validada.

# 20. CENTRO DE PRESSÃO — COP

Implementar cálculo do centro de pressão.

Para uma matriz:

P[i][j]

Calcular:

COPx = Σ(x * P) / ΣP

COPy = Σ(y * P) / ΣP

Aplicar threshold antes do cálculo.

Se a soma de pressão for insuficiente:

COP = null

Evitar divisão por zero.

Mostrar COP visualmente sobre o mapa.
